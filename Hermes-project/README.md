# Hermes: локальный запуск через Docker Compose

## Настройка доступа к dashboard

1. В этой папке скопируй `.env.example` в `.env` (не перезаписывай существующий `.env`).
2. В приватном `.env` задай:
   - `HERMES_DASHBOARD_BASIC_AUTH_USERNAME` — имя пользователя;
   - `HERMES_DASHBOARD_BASIC_AUTH_PASSWORD` — новый стойкий пароль;
   - `HERMES_DASHBOARD_BASIC_AUTH_SECRET` — независимый случайный секрет подписи.
3. Отдельно подготовь `.hermes/.env` с настройками gateway: этот файл указан в
   `env_file` сервиса `hermes` и не заменяет `.env` для подстановок Compose.
4. Из папки `Hermes-project` выполни:

   ```powershell
   docker compose config --quiet
   docker compose up -d
   ```

Compose подставляет параметры dashboard из `.env` рядом с `compose.yaml`
или из окружения процесса. Отсутствующий или пустой пароль/секрет блокирует
запуск: встроенных значений по умолчанию для них нет.

Dashboard опубликован только на localhost: открой `http://127.0.0.1:9119`.
Внутри контейнера он продолжает слушать `0.0.0.0`; ограничение доступа
обеспечивается привязкой опубликованного порта к `127.0.0.1` на хосте.
Публикация порта gateway `8643` этой правкой не изменена; оцени её отдельно,
если компьютер доступен из внешней сети.

## Секреты и история Git

- `.env` и `.hermes/.env` исключены из Git. Публикуется только пустой пример.
- В предыдущей версии `compose.yaml` были фиксированные учётные данные.
  Если они использовались, замени **и пароль, и секрет** до следующего запуска.
- Удаление значений из актуального файла не удаляет их из старых коммитов.
  История здесь намеренно не переписывается. Считай старые значения раскрытыми.
- Исправление конфигурации не меняет уже запущенные контейнеры автоматически.
  После настройки новых значений выполни `docker compose up -d`.
